# DishFinder backend

## Account deletion API

`POST /api/auth/delete-account` deletes the authenticated registered account or
starts an opt-in grace period. This does not delete accounts merely because they
have been inactive. Both verified and unverified registered accounts can use it.

Headers:

```http
Authorization: Bearer <access_token>
Content-Type: application/json
```

`X-Device-Token` may also be supplied, as on other authenticated endpoints.

Request body (both fields required):

```json
{
  "password": "the-user-current-password",
  "grace_period_days": 15
}
```

| `grace_period_days` | Behavior |
| --- | --- |
| `0` | Permanently delete now; cannot be cancelled. |
| `15` | Retain data for 15 days; signing in before the deadline cancels deletion. |
| `30` | Retain data for 30 days; signing in before the deadline cancels deletion. |

Example `200 OK` response for a 15-day request:

```json
{
  "success": true,
  "message": "Account deletion scheduled. Sign in before the deadline to cancel.",
  "status": "scheduled",
  "grace_period_days": 15,
  "deletion_requested_at": "2026-09-29T12:00:00Z",
  "delete_after": "2026-10-14T12:00:00Z",
  "can_cancel": true
}
```

Example `200 OK` response for immediate deletion:

```json
{
  "success": true,
  "message": "Account deleted successfully.",
  "status": "deleted",
  "grace_period_days": 0,
  "deletion_requested_at": "2026-09-29T12:00:00Z",
  "delete_after": "2026-09-29T12:00:00Z",
  "can_cancel": false
}
```

Timestamps are generated by the server in UTC. On a successful request, discard
the account's tokens and cached personal data in the app: every session is
revoked, and pending accounts cannot use protected APIs or refresh tokens.

To cancel during the grace period, use the existing `POST /api/auth/login` with
`X-Device-Token`, and the usual `email` and `password` body. Correct credentials
before `delete_after` clear the request, preserve data, and return the usual login
response with `"account_deletion_cancelled": true`. Old sessions remain revoked;
use the newly returned tokens. Email-verification requirements still apply.
Login at or after the deadline cannot restore the account, even if cleanup has
not run yet. Simply refreshing a token does not cancel deletion.

Cleanup removes the user document, all sessions, favourites, search history,
local subscription records, and the current GridFS profile picture. Device
credentials, guest data, and device search quotas remain because they belong to
the installation and can be shared with other accounts. Account deletion does
not cancel App Store, Google Play, or RevenueCat billing; the app should show
this before the user submits the request.

The API starts a cleanup task on startup and checks every 60 seconds while the
server runs. Expired requests are processed after a restart as well. Database or
file-storage failures leave the account blocked and are retried on subsequent
scans; the user document is removed only after all cleanup steps succeed. Keep
the backend running for timely cleanup. No Mongo TTL index is used for accounts,
since it would skip deletion of related data.

Errors: `401` for missing/invalid authentication or wrong password; `403` for
guest accounts; `422` for invalid payloads; `409` for a competing deletion
request. `503` with `detail.code = "ACCOUNT_DELETION_REQUEST_SAVED"` means the
request was saved, access is blocked, and cleanup will retry automatically.

Run the isolated API/lifecycle and email tests with:

```sh
venv/bin/python -m pip install -r requirements-test.txt
venv/bin/python -m unittest discover -v
```

## Public subscription policy pages

These GET endpoints return mobile-friendly `text/html` without requiring a login,
device token, or subscription:

| Page | Browser URL path | API URL path |
| --- | --- | --- |
| Terms of Use (EULA) | `/terms-of-use` | `/api/terms-of-use` |
| Privacy Policy | `/privacy-policy` | `/api/privacy-policy` |

The existing `/terms-of-service` and `/api/terms-of-service` URLs continue to serve
the same updated terms. Content and shared styling live in `legal_pages.py`.
No additional dependencies or environment variables are required.

After deploying this backend, prepend its public HTTPS origin to either pair of
paths. Open both resulting URLs without signing in to verify the deployed pages.

### Connect the mobile purchase screen

Add visible, tappable **Terms of Use (EULA)** and **Privacy Policy** links to the
subscription screen before the purchase action. Use the deployed HTTPS URLs.
The native app is not part of this repository, so this change only supplies the
destinations for those links.

If the iOS app uses SwiftUI's `SubscriptionStoreView`, set each destination with
[`subscriptionStorePolicyDestination(url:for:)`](https://developer.apple.com/documentation/swiftui/view/subscriptionstorepolicydestination(url:for:)),
using `.termsOfService` and `.privacyPolicy`. The view belongs in the iOS app;
it does not run in this Python backend.

Keep the subscription name, benefits, duration, and store-provided localized
price visible on the purchase screen. In App Store Connect, set the Privacy
Policy URL and include the Terms of Use URL in the app description or applicable
EULA metadata, as requested in the rejection notice.

### Content details to confirm before publishing

- The policy reflects the data handled by this backend. Confirm the mobile app's
  additional SDKs, analytics, advertising, crash reporting, and data sharing are
  also covered before using it as the app-wide privacy policy.
- Confirm the existing `support@dishfinder.online` contact is monitored for
  privacy and deletion requests, and that the retention description matches
  operational practice, including the account-deletion API described above.
- The terms link to Apple's Standard EULA unless the App Store listing supplies
  a custom EULA. Confirm that matches the app's App Store Connect configuration.
- Update the policy text and revision date when data practices or terms change.

Reference: [Apple's subscription review guidelines](https://developer.apple.com/app-store/review/guidelines/#subscriptions).
